**Версия пакета:** 13.10.2026

**Назначение:** обновить код SiteBuilder на существующем Битрикс24 с
PostgreSQL и сохранить действующие данные и права.

- Администраторы SiteBuilder в `config/auth.php`:
  **40, 41, 96, 97, 98, 99**.
- Технический гость: **665**.
- Готовый архив CI также содержит `config/auth.local.php` с теми же ID.
- Исправлено сохранение разрешений администратора и проверка отдельно
  выданного права Диска в режиме `bitrix_disk`.
- Исправление удаления из PR #15 входит в пакет.
- Чтение настроек блока больше не инициирует запись в БД.
- Миграции и таблицы PostgreSQL этим обновлением не меняются.

**Эти ID публикуются в исходном `config/auth.php` репозитория.**
Не используйте этот шаблон для других порталов без замены списка.

## Скачать одним архивом

1. На GitHub открыть **Actions → SiteBuilder ready-to-upload archive**.
2. Выбрать самый свежий успешный запуск для ветки `main`.
3. В **Artifacts** скачать `sitebuilder-ready-to-upload` — один ZIP,
   содержащий всю структуру проекта и готовый `auth.local.php`.
4. Распаковать ZIP на компьютере. В корне архива находятся `api.php`,
   каталоги `api`, `components`, `config`, `lib`, `tools` и т. д.
   Не создавайте второй вложенный каталог `sitebuilder/sitebuilder`.

## Обновить существующий сервер

1. Сделать резервную копию каталога
   `/local/sitebuilder/` и **отдельно** действующей БД PostgreSQL.
   Не удалять старые файлы, пока не будет проверен новый код.
2. Распакованные файлы скопировать **поверх** существующих в
   `/local/sitebuilder/`, разрешив замену файлов.
   **Нельзя** удалять старый каталог и загружать «начисто».
3. Не удалять `/upload/sitebuilder/`, корни папок Битрикс, дисковые права,
   базы данных и служебные каталоги. **Не применять миграции**:
   обновление не добавляет новых миграций.
4. Если приложение размещено на двух файловых серверах без общего каталога,
   обновить файлы на каждом; при наличии OPcache убедиться, что PHP видит
   новый код. Если пользовательский сеанс был изменён, заново авторизоваться.
5. Открыть SiteBuilder и проверить три сценария:
   - администратор Битрикс видит Диск;
   - один из ID 40, 41, 96, 97, 98, 99 видит Диск;
   - обычный сотрудник с заранее выданным доступом видит свою папку,
     а сотрудник с запретом по-прежнему не видит чужую папку.
6. Проверить удаление **только тестового** файла.

## Если доступ не появился

В браузере под администратором портала нажмите F12 → Network/Сеть.
Откройте запрос
`/local/sitebuilder/components/disk/api.php?action=bootstrap` →
**Response**. Интересуют значения:

- `ok`, `error`, `message`;
- `data.settings.permissionMode`;
- `data.permissions.role`, `canView`, `accessSource`;
- `data.rootFolderId`.

Сохраните также ошибки из журнала PHP/Bitrix за это время.
Нельзя делать вывод об удалении прав только по надписи «Нет доступа».
Если `permissionMode=bitrix_disk`, обычный пользователь должен иметь
**и** право на Диск SiteBuilder, **и** соответствующее право на физическую
папку Битрикс.

**Не запускайте массовую синхронизацию групп с удалением несоответствий,
не очищайте ACL и не переустанавливайте модуль** во время диагностики.

## Откат

При сбое вернуть сохранённую копию каталога `/local/sitebuilder/`
(либо прежде всего `config/auth.php`, `config/auth.local.php` и
затронутые файлы `components/disk/`). Откат кода не заменяет резервное
копирование реальной БД и диска Битрикс.
