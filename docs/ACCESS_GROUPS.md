# Группы доступа Sitebuilder — этап 25

Новая страница: `/local/sitebuilder/groups.php`. Вход также через ссылку «Группы доступа» в персональной админке `/local/sitebuilder/access.php`. Визуальный референс — [ColorlibHQ/AdminLTE](https://github.com/ColorlibHQ/AdminLTE): боковая панель и карточки. Реализация собственная, локальные CSS/JS, без CDN, Bootstrap, jQuery и внешних шрифтов; стили изолированы префиксом `sbg-`, без `!important`.

## Модель и интерфейс

Администратор Sitebuilder или Битрикс создаёт и переименовывает локальную группу. Вкладки: «Участники», «Права», «История». Список сотрудников принимает до 5 000 строк из Excel: ФИО, логин, email, ID. Сопоставление повторно использует проверенный резолвер; однофамильцы выбираются вручную, повторы не создают записи повторно, технический гость и неактивные сотрудники не добавляются. Операции идут пакетами по 100; API принимает до 500 ID в одном пакете. Состав отображается постранично по 100. Группа не ограничена первыми 100 сотрудниками.

Права можно назначать на сайт (просмотр/редактирование его страниц), конкретную страницу (с наследованием на дочерние по флажку), блок Диска или папку (просмотр, редактирование, удаление — независимые флажки). Редактирование подразумевает просмотр. Для групп редактирование файлов **не** выдаёт удаление. Перемещение требует изменения и удаления в источнике и изменения в назначении. Папочный доступ относится к выбранному блоку, текущему корню и режиму Диска; при изменении корня/режима правило нужно явно пересохранить.

Групповые правила только разрешающие. Удаление правила снимает этот источник, но не запрещает доступ от остальных. Разрешения групп и независимых личных назначений объединяются. Явный персональный запрет страницы/папки приоритетнее групп. Защищённые административные роли сохраняют прежние возможности. Группа не получает управление правами, настройки сайта или OWNER/ADMIN.

Для папки можно явно включить «Открывать страницу с этим диском». Это даёт только просмотр страницы контейнера, не всех страниц сайта и не других блоков Диска. При доступе только к вложенной папке родительские папки используются для перехода, без чтения их файлов и без просмотра соседних веток. Файловые API, поиск и скачивание проверяют те же разрешения. Рекурсивное удаление/копирование/переименование папок не разрешается через скрытые вложенные папки; лимит проверки — 2 000 папок, превышение завершает операцию отказом. Удалить назначенный корень через его недоступного родителя нельзя; разрешение касается содержимого разрешённой области.

Существующая роль EDITOR для персональных назначений не переопределяется: она могла уже разрешать удаление. Поэтому флажок удаления выключен у группы не означает запрет удаления, если право есть лично или через другую группу. Проверяйте итоговые права обычного пользователя.

## Точный смысл режима bitrix_disk

Группы локальные: **не создают штатные группы Битрикса и не записывают их ACL**. В `custom` и `inherit_site` действуют локальные групповые разрешения. В `bitrix_disk` группа не может предоставить больше, чем разрешает штатный ACL физической папки. Для пользователя, получившего доступ только через новые группы, используются пересечение его групповых операций и штатных возможностей. Старый персональный доступ сохраняет прежнюю нативную семантику.

Таким образом, группа с «редактированием без удаления» не получает удаление лишь потому, что штатный ACL шире. Но при отсутствии штатного права просмотра на папку локальная группа не откроет её в нативном режиме. Это подписано рядом с настройкой; автоматического переключения режима или переноса прав на весь портал нет. Полностью самостоятельная раздача внутри Sitebuilder использует локальные режимы. На рабочем портале режимы без согласования не менять.

## Хранение и безопасность

Новая дополняющая миграция `20261015_013_access_groups.sql`, этап **25**, создаёт три таблицы:

- `sitebuilder.access_group` — название, версия и автор;
- `sitebuilder.access_group_member` — состав;
- `sitebuilder.access_group_rule` — ресурс и разрешения.

История и квитанции повторов — существующий `sitebuilder.audit_log`, `entity_type=access_group`, действия `accessGroup.*`. Членство не материализуется в U-назначения. Удаление группы каскадно удаляет только её состав и правила; аудит остаётся. Личные права, другие группы, пользователи Битрикса и файлы не удаляются. Никакой очереди, worker, `corp.access` или внешней синхронизации для выдачи не требуется.

Каждый запрос проверяет административный доступ и sessid на сервере. Изменения группы сериализованы row lock + ожидаемой версией. requestId и транзакционная квитанция предотвращают повторную запись, включая потерю ответа создания/удаления. Ошибка одного пользователя откатывает целиком текущий пакет; ранее подтверждённые пакеты сохраняются. Права пересчитываются при следующем запросе пользователя, без перезаписи личной матрицы. Уже начавшийся запрос может завершиться со своей ранее вычисленной картиной доступа.

Визуальная проверка наследования выполняется настоящей текущей иерархией папок, не сохранённым путём. Межсайтовые/межблочные подмены отклоняются. Общая проверка прав сохранена для списка, просмотра, загрузки и удаления. Native ACL не обходится. Сохраняются персональные запреты и исключения администраторов.

Попутно исправлен выбор миграции реестра в bootstrap: используется явно этап 13, а не последний элемент манифеста. Иначе добавление очередного этапа могло ошибочно записать его как выполненный без SQL. Старые SQL-файлы и checksum не изменены.

## Установка только на тестовую копию

Пакет является дополнением к проверенному `main` 974717a; он не является полным проектом и не восстанавливает отсутствующий в main старый функционал универсальных списков. Не заменяйте рабочую папку целиком этим обновлением. Сохраните копии изменяемых файлов, схемы PostgreSQL и ваших локальных настроек.

1. Загрузить новые/изменённые рабочие файлы поверх `/local/sitebuilder/`. `config/auth.php`, `config/auth.local.php`, `pg_master.php` и `/urlrewrite.php` не входят в обновление.
2. На тестовом домене открыть `/local/sitebuilder/deployment.php`. Ожидается только новый этап 25, без конфликта номера и checksum. Если этап занят — остановиться, не исправлять реестр вручную.
3. Применить ожидающую миграцию. Открыть `/local/sitebuilder/groups.php`.
4. Создать группу с двумя обычными тестовыми пользователями, назначить просмотр страницы и изменение тестовой папки без удаления. Проверить вход под обычным пользователем, а не администратором.
5. Проверить удаление участника, пересечение двух групп, личное право, персональный запрет и соседнюю закрытую папку. Нативный режим проверять отдельно; его штатные права не копируются группой.

На сервере не нужны команды оболочки. Битрикс + pgAdmin достаточны. Worker не запускать. Для крупных списков сначала проверить 2–3 пользователя, затем расширять.

Дополнительно проходят прежние проверки индивидуальных прав.

`tests/access_groups_browser_test.py`: Chromium, настоящий JS/CSS, подменённый API. 501 сотрудник, 6 пакетов, дубликаты, выбор однофамильца, права папки, повтор после потери ответа, удаление группы, безопасность вывода HTML и мобильная ширина.

PostgreSQL-тесты создают/удаляют **только** отдельную БД-схему внутри базы `sitebuilder_access_test` с `SB_ACCESS_TEST_ALLOW_RESET=1`. Нельзя запускать их на `bx` или рабочем сервере. Проверки с фикстурами не заменяют проверку вашей коробки Битрикс.

## Откат

Возврат старых файлов отключит групповые разрешения; личные права в БД остаются. Новые таблицы не удалять автоматически. Перед откатом учесть сотрудников с доступом только через группы. После применения явных запретов страниц старый код, игнорирующий deny_view, возвращать нельзя.
