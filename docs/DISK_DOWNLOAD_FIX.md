# Исправление скачивания файлов из Диска Sitebuilder

## Причина прежней ошибки SERVER_ERROR

В `components/disk/actions/download.php` выполнялся вызов
`$file->getDownloadUrl()`. У модели `Bitrix\Disk\File` такого
метода нет. Соответствующее исключение скрывал общий обработчик
`components/disk/api.php`, поэтому пользователь видел
`{"error":"SERVER_ERROR","message":"Внутренняя ошибка сервера."}`.

Кроме того, в старом обработчике результат корректно построенного URL
из `DiskBitrixStorageAdapter::getDownloadUrl()` сохранялся в `$url`,
но далее никак не использовался.

## Новое поведение

- Проверяется авторизация, принадлежность файла сайту и права
  `canDownload` на родительскую папку по принятому в Sitebuilder
  режиму разграничения доступа.
- Объект `Bitrix\Disk\File` преобразуется в физический массив
  `b_file` с помощью `$file->getFile()`; затем вызывается
  `\CFile::ViewByUser($fileData, ['force_download'=>true, ...])`.
- Это не делает редирект на нативный адрес Диска, где права могут
  отличаться от прав, заданных через Sitebuilder.
- Используется нативный механизм отдачи файлов Битрикс, включая
  зарегистрированные обработчики внешних файловых хранилищ.
- До передачи файла освобождается блокировка пользовательской сессии
  и очищаются буферы PHP; файл скачивается под своим именем.
- Ошибки получают понятный HTTP-статус и код `SD-DL-...`.
  В PHP error log по этому коду доступны этап, ID пользователя и
  файла, группы и эффективные права родительской папки, исходное
  исключение. Технические детали в HTTP-ответе видны только
  администратору Битрикс.
- Операция чтения не изменяет ACL, свойства блоков или PostgreSQL.
  Никаких миграций нет.

## Как безопасно установить

Если полный готовый проект Sitebuilder уже находится на сервере,
замените **только**:

```text
/local/sitebuilder/components/disk/actions/download.php
```

Сначала сохраните копию старого файла для отката. Не трогайте
`config/auth.php`, `config/auth.local.php`, базу, папки Диска.
На кластере с раздельными файлами приложения замените файл на всех
веб-узлах. При OPcache убедитесь, что PHP увидел изменения.

Обновлённый проект также доступен готовым архивом из Workflow
**SiteBuilder ready-to-upload archive** в GitHub Actions; при
загрузке полного архива обязательно сохранять каталог сервера и БД,
переносить файлы поверх существующей установки, без удаления каталога.

## Проверка

1. Под администратором Битрикса скачайте небольшой тестовый файл.
2. Под обычным сотрудником с `canDownload` скачайте файл, на
   который есть разрешение.
3. Убедитесь, что пользователь без доступа не может скачать этот
   файл по скопированной ссылке (HTTP 403).
4. Убедитесь, что имя файла корректно отображается при скачивании.
5. Если возникает ошибка, откройте новую вкладку со скачиванием.
   Для администратора JSON теперь содержит
   `details.technicalError`, а `details.diagnosticId` соответствует
   строке `SiteBuilder Disk download error` в журнале PHP.

Работа непосредственно на сервере Битрикс24 требует отдельной
проверки после загрузки; тесты GitHub заменяют только внешние
зависимости тестовыми моделями.
