# Названия диска и папок

Название диска на публичной странице, в его настройках и в цепочке папок
берётся из имени привязанной папки Битрикс24.Диска. Привязка остаётся по ID:
переименование не создаёт папок и не перемещает файлы.

- Сохранение названия в настройках диска или изменение заголовка дискового
  блока в редакторе переименовывает его текущую корневую папку на портале.
- При выборе другой существующей корневой папки принимается её название.
  Чтобы переименовать выбранную папку, затем измените название диска.
- Изменение на портале видно после открытия страницы или нажатия «Обновить»
  в диске. У блоков, использующих одну папку, отображается одно название.
- Подпапки уже являются объектами Битрикс. Их имена и цепочка навигации
  читаются напрямую; результат операции переименования теперь проверяется.
- Новая отдельная папка блока создаётся с названием диска, без префикса «Блок».

Существующие папки не переименовываются при просмотре страницы. После обновления
показывается их фактическое имя на портале. Для смены имени используйте настройки
диска. Название сайта и адрес сайта не меняются.

## Сохранение и ошибки

`lib/DiskTitleSyncService.php` вызывается из `RevisionService::saveBlock`
после проверки версии. Сохранение настроек и постановка `disk.title.sync`
в существующую таблицу `sitebuilder.outbox_job` входят в одну транзакцию.
После COMMIT выполняется немедленная попытка через `ExternalJobWorker`.
Если она не удалась, существующий воркер очереди повторит задачу. Новая миграция
БД не требуется; штатный запуск воркера должен быть настроен для повторов.

Задача хранит ID папки, исходное и желаемое имена. Перед выполнением повторно
проверяются привязка, актуальность названия блока и права инициатора. Устаревшие
задачи пропускаются. Если имя на портале уже отличается от исходного, операция
завершается `DISK_TITLE_CONFLICT` и не переименовывает папку.
Проверка исходного имени также выполняется при сохранении открытых настроек.
Это проверка снимка имени, а не распределённая блокировка интерфейса Битрикс.

При временной ошибке окно настроек сообщает об отложенной синхронизации;
на странице остаётся фактическое имя папки. Ошибки доступны и в штатной очереди.
Повтор операции с уже применённым именем не вызывает нового переименования.
В `props.title` хранится последний запрос из конструктора; чтение имени из
Битрикс не создаёт фоновых редакций блока. Поэтому сохранённая подпись блока
в редакторе может отличаться после переименования непосредственно на портале;
публичный диск и его настройки показывают имя Битрикс.

## Проверка

```sh
php tests/disk_title_sync_test.php
php tests/disk_quota_test.php
node tests/disk_title_ui_test.js
node tests/disk_capacity_ui_test.js
npm run test:styles
npm run test:styles:browser
```

Браузерный тест использует настоящий PHP-шаблон и JavaScript компонента,
а API и Битрикс заменяет тестовыми ответами. Можно задать `PHP_BIN` и
`CHROMIUM_EXECUTABLE_PATH`. PHP-тест проверяет сервис, адаптер, повторы,
смену корня, конфликты имён, права и обработку отказов. Он не запускает
реальную БД портала. После установки проверить сохранение имени и обратное
переименование на тестовом Битрикс, включая два блока с общей папкой.
