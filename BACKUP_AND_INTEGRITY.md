# Резервные копии и проверка целостности — этап 12

## Назначение

Этап 12 добавляет переносимый резервный пакет одного сайта и проверку логической целостности данных SiteBuilder.

Резервная копия содержит:

- настройки сайта;
- страницы и иерархию;
- блоки;
- секции страниц;
- layout;
- меню;
- при явном выборе — прямые роли и точечные права;
- диагностический отчёт целостности на момент создания.

Не включаются:

- содержимое Битрикс.Диска;
- CFile-файлы логотипа, фона и загруженных изображений;
- ID рабочей группы Битрикс24;
- ID папки Битрикс.Диска;
- история ревизий, журнал действий и очередь;
- роли `OWNER` исходного сайта.

После восстановления создаётся новый сайт, новый пользователь становится его `OWNER`, а группа и папка ставятся в очередь на создание.

## Установка

1. Установить этап 11.
2. Сделать резервную копию PostgreSQL и `/upload/sitebuilder`.
3. Развернуть файлы этапа 12.
4. Применить `migrations/20260729_007_backups_and_integrity.sql` или открыть:

```text
/local/sitebuilder/tools/apply_stage12_migration.php
```

5. Для этапа 12 PHP должен был иметь доступ к `/upload/sitebuilder/backups`. Начиная с этапа 13 новые копии сохраняются вне `DOCUMENT_ROOT`, а старые файлы переносятся автоматически.
6. Очистить OPcache.

## Интерфейс

```text
/local/sitebuilder/backups.php?siteId=13
```

`ADMIN` и `OWNER` могут создавать, проверять и скачивать копии. Включение прав, импорт, восстановление и удаление требуют `OWNER` либо администратора Битрикс. `ADMIN` сайта может создавать копию без прав и запускать проверку целостности.

## Импорт скачанного пакета

На странице резервных копий `OWNER` может загрузить ранее скачанный `.json` или `.json.gz`. Пакет проверяется по формату и ограничению размера, после чего заново упаковывается и получает собственную SHA-256 запись в реестре.

Права из импортированного файла всегда отбрасываются. Коды вида `U123` и `G45` являются локальными числовыми идентификаторами Битрикс и на другом портале могут принадлежать другим людям или группам. Контент импортируется, а владельцем восстановленного сайта становится пользователь, запустивший восстановление.

## Формат хранения

Пакет хранится как JSON или JSON.GZ. Для каждого файла сохраняются SHA-256, размер и версия формата. Запись выполняется во временный файл с последующим атомарным `rename()`. Локальные ID файлов и папок очищаются, поэтому после восстановления изображения оформления и содержимое Диска нужно загрузить заново.

Путь файла хранится только как имя внутри служебного каталога. Значения с `../` и абсолютные пути не принимаются. Начиная с этапа 13 каталог по умолчанию расположен вне web-корня: `dirname(DOCUMENT_ROOT)/sitebuilder-private/backups`. Его можно переопределить параметром `absolute_directory` в `config/backup.php`.

## Восстановление

Восстановление не изменяет исходный сайт. Создаются новые ID сайта, страниц, блоков, секций и меню. Внутренние ссылки пересчитываются по карте ID.

При восстановлении прав:

- `OWNER` не переносится;
- для локально созданной копии разрешены только `ADMIN`, `EDITOR`, `VIEWER`;
- импортированный файл всегда восстанавливается без старых прав;
- точечные права страниц привязываются к новым ID страниц;
- некорректные или отсутствующие связи пропускаются.

## Проверка целостности

Проверяются:

- главная страница и верхнее меню;
- наличие layout;
- наличие прямого владельца;
- родительские связи и циклы страниц;
- повторяющиеся slug среди соседних страниц;
- связи блоков и секций;
- placement блока в секции другой страницы;
- ссылки меню на отсутствующие страницы;
- точечные права на отсутствующие страницы;
- наличие привязок к группе и папке Диска.

Проверка ничего не исправляет автоматически. Это сделано намеренно: сомнительные исправления должны выполняться администратором после анализа отчёта. Неудачный запуск сохраняется в истории со статусом `failed` даже после отката основной API-транзакции.

CLI:

```bash
DOCUMENT_ROOT=/home/bitrix/www \
php /home/bitrix/www/local/sitebuilder/tools/integrity_check_cli.php --site=13
```

Коды завершения: `0` — ошибок нет, `1` — обнаружены ошибки, `2` — проверка не выполнена.

## Retention

Срок хранения новых копий задаётся в `config/backup.php`. Автоматическое обслуживание помечает просроченные копии удалёнными и удаляет файлы после успешного COMMIT.
