# Авторизация SiteBuilder

## Что уже подключено

- `login.php` принимает обычный логин/пароль Битрикс и предоставляет кнопку гостевого входа.
- `index.php`, `editor.php`, `files.php`, `layout.php`, `menu.php`, `settings.php` и `public.php` перенаправляют неавторизованного пользователя на `/local/sitebuilder/login.php`.
- Основной API возвращает `401 AUTH_REQUIRED` и ссылку на страницу входа.
- Публичный рендер показывает только опубликованные страницы, доступные текущему пользователю по глобальной роли или `page_access`.
- Действия Диска дополнительно проверяют принадлежность файла/папки разрешённому корню.

## Настройка гостя

1. Создать отдельного активного пользователя Битрикс без группы администраторов.
2. Указать его ID в `config/auth.php` (`guest_user_id`).
3. В интерфейсе SiteBuilder назначить этому пользователю прямую роль `VIEWER` на нужные сайты.
4. Не полагаться только на роль участника группы Битрикс: компонент Диска читает прямые записи `sitebuilder.access` и коды групп Битрикс.
5. На уровне Битрикс.Диска оставить только чтение/скачивание нужного storage/root.

## Администраторы SiteBuilder в коде

В `config/auth.php` заполнить `admin_user_ids` числовыми ID пользователей Битрикс:

```php
'admin_user_ids' => [
    123,
    456,
],
```

Это пример: в поставляемой конфигурации список пуст, реальные ID нужно указать
самостоятельно. Изменение применяется при следующем запросе; при отключённой
проверке изменений файлов в OPcache нужно сбросить кеш штатным способом.

Единая проверка — `sitebuilder_is_admin()` в `lib/auth.php`. Она разрешает
администрирование всех сайтов конструктора пользователям из списка и штатным
администраторам Битрикс. Проверка используется в интерфейсе, API, правах страниц,
списках и компоненте Диска. `sitebuilder_is_admin($userId)` рассчитывает доступ
конкретного пользователя, не переносит полномочия текущего администратора на
другие ID.

Список редактируется только в PHP: формы настройки и API для него нет. Вход
остаётся через обычную авторизацию Битрикс. `guest_user_id`, нули и некорректные
значения не получают административный доступ через этот список.

Добавление ID не меняет группы пользователя и не даёт административных прав на
сам портал Битрикс. Диагностика, миграции, установка маршрутов, сброс OPcache и
страницы развёртывания по-прежнему требуют администратора Битрикс. Штатные ссылки
и просмотрщики Битрикс.Диска по-прежнему проверяют нативные ACL; их синхронизация
выполняется существующим механизмом прав SiteBuilder.

## Важно

Общий технический пользователь подходит только для режима чтения. Все гостевые сессии будут отображаться в аудитах Битрикс как один пользователь.
