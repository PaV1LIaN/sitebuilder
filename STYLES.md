# Стили SiteBuilder

У каждого компонента есть основной файл со стилями. Исторические цепочки
`editor-v2.css` … `editor-v16.css` и `responsive-stage*.css` удалены.
Правило следует менять на месте, а не перекрывать новой копией в конце файла.

## Каскад

Публичная страница подключает основу, навигацию и стили компонентов,
затем секции, пользовательскую адаптивность и состояния анимации.
Порядок виден в `views/layout/public_page.php`. Редактор подключает
`admin.css`, один `editor.css`, затем специализированные формы и списки.

Внутри файла правила сгруппированы по компонентам. Модификаторы и состояния
относятся к конкретному компоненту. Адаптивные правила дополняют его базовое
состояние. Для закрытых окон и скрытых элементов используется `hidden` или
существующий класс `sb-hidden`; правила показа не должны включать такие элементы.

Принудительный приоритет запрещён и в CSS, и в JavaScript. Если правило
не применяется, сначала проверить порядок файлов, специфичность и inline-стиль.
Не дублировать селектор и не создавать новый файл с очередным исправлением.

## Значения из настроек

PHP передаёт пользовательские размеры, цвета и отступы через CSS-переменные.
Например, размер заголовка хранится в `--sb-heading-size`, а размер
логотипа — в `--sb-logo-size`. Обычные CSS-свойства читает stylesheet компонента.
Действительно динамические размеры колонок таблицы может устанавливать JavaScript.

Обёртка адаптивного блока имеет `data-sb-responsive-type` и список явно
заданных свойств в `data-sb-responsive`, например `tablet-size mobile-align`.
Значения лежат в переменных `--sb-r-tablet-size`, `--sb-r-mobile-align` и т. п.
Отсутствующее свойство не сбрасывает базовую настройку компонента. На телефоне
продолжает действовать настройка планшета, пока для телефона не задана своя.

Для изображения, hero и разделителя переменные исходной конфигурации содержат `config`
в имени. Это позволяет адаптивности менять итоговое значение без борьбы
с inline-переменными. Высота секции читается из `--sb-section-min-height`.

## Проверка изменений

Зависимости ниже нужны только разработчику; работа PHP-приложения их не требует.

```sh
npm ci
npm run test:styles
npx playwright install chromium
npm run test:styles:browser
```

Проверка стилей ищет запрещённые приоритеты и разбирает CSS. Браузерная
проверка загружает стили в порядке настоящих PHP-страниц и проверяет
представительные фрагменты разметки на ширинах 1440, 768 и 390 px.
Дополнительно выполняются настоящее перетаскивание колонок таблицы и
проверки пользовательских настроек адаптивных блоков. Проверяются также
состояния окон, скрытие и анимация. Это не запуск Bitrix:
доступы, данные и сторонние расширения проверяются отдельно на тестовом портале.

Для сравнения со старой версией можно передать локальную копию исходников:

```sh
node tests/styles_browser_test.js --baseline /path/to/previous-version --report /tmp/styles-diff.json
```

После обновления CSS менять версию URL в затронутых подключениях. При этом
рефакторинге используется `?v=20260917`. На сервер следует переносить всю
версию проекта целиком: PHP-разметка, переменные, CSS и обновлённый JS связаны.
